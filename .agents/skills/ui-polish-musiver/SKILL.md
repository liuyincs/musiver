# ui-polish-musiver

Musiver 官网（排除文档页） 的界面地图和打磨流程。本目录里：

- `config.json`：达标阈值、每批数量、平台、平台族、主题。
- `screens/<id>.json`：每个界面的状态、源码路径和各格分数，字段见 [`map-format.md`](map-format.md)。
- `blueprints/<名字>.md`：一组界面的布局蓝图。
- [`rubric.md`](rubric.md)：本仓库的评分维度和评审补充，原样拼进评审提示词。
- `assets/review-calibrate.md`、`assets/review-polish.md`：定调轮和打磨轮的评审提示词模板，`ui-shots prepare` 用它们生成每一轮的 `prompt.md`。
- `assets/page.html`：网页模板，`ui-shots page` 用它把截图、分数和过程记录做成网页。
- `scripts/ui-map.mjs`：读写地图的唯一入口。下文的 `ui-map` 都指 `node .agents/skills/ui-polish-musiver/scripts/ui-map.mjs`。
- `scripts/ui-shots.mjs`：一轮截图的校验、拼图、生成提示词、沿用分数、合并评审结果和生成网页。下文的 `ui-shots` 都指 `node .agents/skills/ui-polish-musiver/scripts/ui-shots.mjs`。

两个脚本都用 `--help` 查看命令。`map-format.md`、`assets/` 和两个脚本由 `create-ui-polish-skill` 维护，升级时会被覆盖，本仓库的内容写在其他文件里。

布局相近的平台归为一个平台族（`config.json` 的 `families`）：desktop = web-desktop（1440×900）；phone = web-phone（390×844）；tablet = web-tablet（820×1180）。蓝图的「共通」一节（信息结构、状态、产品约束）全应用一致；每个平台族有自己的「布局」一节，写本族现有的布局，同族平台按它对齐，不同族之间不要求布局相同。

### 打磨范围

每个界面在本族第一次打磨时走**定调轮**：评审员看图打分，同时起草这个界面的打磨范围，分「锁定」和「可调」两部分；用户看过截图后确认或修改，写进蓝图本族「布局」一节的 `### 打磨范围：<界面 id>`。之后同族各平台打磨这个界面都是**打磨轮**，只改「可调」的部分，幅度不超过写明的范围。`ui-shots prepare` 按蓝图里有没有这一小节决定是哪种轮次。

放开锁定项、改变布局或扩大幅度都由用户决定：先改蓝图里的打磨范围或布局，并在「决定记录」里写明理由。

### 蓝图改动与过期

蓝图改动不会自动让分数过期。改完蓝图，先看改的是哪一节，再判断哪些平台受影响：

- 改了某个平台族的「布局」：只可能影响同族的平台。
- 改了「共通」：可能影响所有平台族。

然后逐个判断受影响范围内的平台，现有界面还符不符合新蓝图：

- **不符合**：比如区块顺序变了、主操作换了位置、某个状态多了或少了元素。对受影响的界面、平台、状态运行 `ui-map invalidate <界面>... --platform <平台> [--state <状态>] --reason <改了什么>`。整组界面都受影响时用 `--blueprint <名字>` 代替界面列表；整族平台都受影响时用 `--family <族>` 代替平台列表。
- **仍然符合**：比如措辞调整、补充已经成立的产品约束、追加决定记录，或者在「族内允许的差异」里登记某个平台自己的做法。这些情况不标记过期。
- **发起改动的平台**：本轮会重新评分，`record` 会覆盖旧分数，不需要标记。

拿不准某个平台是否受影响时，就标记过期。多评一次的代价，比带着偏离继续发布小。

## 修改界面之后

新增、修改、删除界面的提交里同时更新地图：

1. 新增界面或状态：在 `screens/<id>.json` 里补全 `states`、`sources`、`blueprint` 和 `priority`。新状态截不到时，按「截图」一节补好截图入口；补不了就写进 `gaps` 并注明原因。
2. 删除界面：从地图里删掉对应文件。某个平台不再提供：写进 `unsupported`。
3. 改动改变了蓝图描述的布局或状态：同一提交里改蓝图，追加「决定记录」，并按「蓝图改动与过期」处理其他平台的分数。
4. 运行 `ui-map check`。完成标准：没有「错误」，也没有「注册表里有，地图里没有」。「已过期」的提示是正常的，这些格子下次打磨时会被挑中，不需要当场重新评分。

## 打磨一批

1. **确认评审员和参数。** 评审员由用户在本次请求里指定（模型、harness 或渠道）。没指定时先请用户指定，指定前不开始评分。阈值和每批数量取 `config.json`。用户在本次给了新值时，运行 `ui-map config threshold <值>` 或 `ui-map config batchSize <值>` 保存下来，随本次提交。
2. **挑界面。** 运行 `ui-map next --platform web-desktop,web-phone,web-tablet`。本机负责全部 Web 形态，无设备分工约定。输出就是这一批的界面和每一格的现状，按平台族分组，并列出同族已达标的「参照」平台，不需要再读整张地图。
3. **截图。** 按「截图」一节，把这批界面在本机平台上的每一格（每个主题 × 每个状态）截进一个新的轮次目录，目录格式见 [`map-format.md`](map-format.md) 的「截图轮次」。同一批的各轮放在同一个批次目录下，按 `round-1`、`round-2` 依次编号，第一轮就是打磨前的画面。`gap` 格先补截图入口、删掉 `gaps` 条目，再截图。本机也能截参照平台时，把参照平台的同一组状态截进另一个目录，作为对齐用的参照图，不参与评分。然后运行 `ui-shots verify <轮次目录>`。完成标准：`verify` 没有错误。
4. **评审。** 运行 `ui-shots prepare <轮次目录>`（有参照图时加 `--ref <参照目录>`）。它会拼好送审图片，写出这一轮的评审提示词 `prompt.md`，并报出这是定调轮还是打磨轮。开一个新的评审会话，把 `prompt.md` 的全文原样发给评审员，作为这个会话里唯一的消息。评审员回复的 JSON 存成轮次目录里的 `review.json`，运行 `ui-shots merge <轮次目录> --review <轮次目录>/review.json`。`merge` 报出缺格、缺修改建议或缺打磨范围草案时，在同一个评审会话里让评审员补齐，再重新合并；`opened` 没有覆盖全部送审图片时，这一轮作废，换新会话重评。完成标准：`merge` 写出了 `scores.json` 和 `suggestions.json`。

   你自己判断截图时只看 `prepare` 和 `merge` 的输出；要核对某一格，就打开它所在的那张拼图。
5. **定调（只在定调轮）。** 运行 `ui-shots page <轮次目录> --out <批次目录>/calibrate.html`，把网页的绝对路径发给用户；所在环境能直接渲染 HTML 时一并展示。请用户逐个界面确认或修改打磨范围草案，并对方向性建议（`D` 编号）表态。用户确认后，把结果写进蓝图本族「布局」一节：

   ```markdown
   ### 打磨范围：<界面 id>

   锁定：
   - <元素>：<原因>

   可调：
   - <元素>：<幅度>
   ```

   在「决定记录」里追加一行，提交蓝图。用户放开的方向性建议，按「打磨范围」一节先写进蓝图，再当作采纳的建议去改。完成标准：本轮每个定调界面在蓝图里都有用户确认过的打磨范围。之后的步骤自主完成，直到第 9 步汇报。
6. **修改。** 改动只来自 `suggestions.json`：`S` 是修改建议，`M` 是与蓝图不一致，默认按蓝图改回来。逐条决定采纳或不采纳。超出打磨范围、与蓝图或产品约束冲突、与同轮其他建议矛盾的不采纳；采纳的按建议的方向和幅度改。`D` 方向性建议留给用户，这一轮不动。处理结果写进轮次目录的 `changes.json`：

   ```json
   { "adopted": [{ "id": "S1", "change": "改了什么" }], "declined": [{ "id": "S2", "reason": "为什么不采纳" }] }
   ```

   不采纳的原因是某条约束还没写进蓝图时，把这条约束补进「产品约束」并注明出处，下一轮评审员就能看到。完成标准：每条 `S`、`M` 都出现在 `changes.json` 里，每处界面代码改动都对应一条采纳的建议。
7. **复评。** 把这一批的全部格子重新截进下一个轮次目录，从第 3 步再走一遍，`prepare` 加 `--prev <上一轮目录>`。`prepare` 只送画面变了的拼图，其余格子沿用上一轮的分数。本轮改了蓝图里本族的布局或「共通」时，改加 `--fresh`，让评审员按新蓝图重看全部格子。出现下面任一情况就停：一个界面所有格都达到阈值；`suggestions.json` 里没有可采纳的建议；最低分连续两轮没有超过此前最好的最低分。后两种把卡住的原因写进汇报。
8. **记录。** 先提交界面改动和蓝图改动，然后运行 `ui-map record --from <最后一轮目录>/scores.json`，它会写入每一格的分数、扣分点和画面哈希。最后提交地图。
9. **汇报。** 按顺序把这一批的全部轮次传给 `ui-shots page <round-1> <round-2> ... --out <批次目录>/report.html`，`page` 报出「changes.json 没有交代」时先补齐再生成。把网页的绝对路径发给用户，网页里有打磨前后的截图对比和每一轮的分数、建议与采纳记录。汇报里再列出：每个界面打磨前后的最低分、仍未达标的格子和原因、补上的截图入口、待用户决定的方向性建议，以及 `ui-map status --platform <本机平台>` 的汇总。

## 截图

截图命令要满足三条，`ui-shots` 依赖它们：

- **写清单。** 一次命令截一轮，把图片和 `manifest.json` 写进指定的轮次目录（格式见 [`map-format.md`](map-format.md) 的「截图轮次」）。
- **就绪断言。** 截图前确认已经进入目标状态：等状态标记出现、数据加载完、滚动到位。断言失败就报错退出，不输出图片。`verify` 只能查出「截全了没有」「不同状态是不是同一张图」，截到的内容对不对由这条保证。
- **稳定。** 同一构建把同一批格子连拍两轮，`ui-shots compare <轮次A> <轮次B>` 全部一致。状态栏的时间和电量、播放进度的时间这类每次都会变的区域，写进 `manifest.json` 的 `ignore`，算画面哈希时跳过；截图本身照常保留它们，评审员看到的不变。只框真正会变的那一小块，框进去的部分改了样式也不会触发复评。动画和光标闪烁靠等待或关闭来稳定。仍然做不到的平台在下面写明原因，这个平台的分数每轮都会重评。

拼图需要本机装有 ImageMagick（`magick`）或 ffmpeg。ffmpeg 找不到标签字体时，用环境变量 `UI_SHOTS_FONT` 指定一个字体文件。

从仓库根运行：

```sh
pnpm build
pnpm ui:capture --platform web-desktop --screen home --out /tmp/ui-polish-musiver/home/round-1
pnpm ui:shots verify /tmp/ui-polish-musiver/home/round-1
pnpm ui:shots prepare /tmp/ui-polish-musiver/home/round-1
```

命令自动在随机本地端口启动 build 静态服务，退出时关闭；无需手动启动服务器。默认使用本机已安装的 Google Chrome（独立无头临时会话）；其他机器先安装 Chrome，或运行 `pnpm exec playwright install chromium` 后追加 `--browser chromium`。拼图使用本机 ffmpeg；缺少时 `brew install ffmpeg`。
`--platform` 每次选一个；省略 `--screen` 截全部适用界面。可加 `--theme light`、`--state en_default` 截单格用于调试；verify 要求该界面的全部格，正式轮次省略这两项。
语言是状态前缀，通过真实的 `/` 和 `/zh-Hans/` 路由呈现。下载状态通过真实按钮依次选择平台和渠道；数据直接使用 src/data/releases，不伪造发布信息。导航通过真实语言下拉和移动菜单按钮打开。
截图等待 React hydration、h1、字体及所有图片加载完成，并断言主题、语言、选中按钮或菜单展开状态；关闭 CSS 动画与过渡，固定设备像素比为 1，整页截图，无系统状态栏，ignore 为空。新增状态同时改 screens 和 scripts/capture-ui.mjs，保留真实操作与就绪断言。
输出目录必须在仓库外；manifest、截图和评审数据均不提交。本机使用 Chrome 无头独立会话、禁用 GPU，样式关闭动画后等待两帧绘制；第二轮首页四格连拍 compare 全部一致。ignore 保持为空；修改截图协议或浏览器版本后重新比较。

范围与逐项核对见 [inventory.md](inventory.md)。`/docs/**`、文档搜索和文档专用导航不纳入本技能。国际化内容变更同时维护英文与简体中文键值；技能和机器配置本身不引入页面文案键。
